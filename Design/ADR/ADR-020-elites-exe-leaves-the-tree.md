# ADR-020 — ELITES.EXE leaves the tree (D28)

**Status:** accepted 2026-10-10, with the change that implements it. It records the owner's ruling D28 ([Reverse-Engineering-Plan.md §8](../Reverse-Engineering-Plan.md#8-decisions-for-the-owner)), and amends ADR-002 item 2 and ADR-019 item 3. **Amended 2026-10-11 (D35, D36):** of the scripts that read the file by hand, `ScanReference.py` and `ReferenceScreens.py` are deleted, `GenerateReference.py` goes with piece 3's change 2, and `MapReference.py` stays as a research tool. Since [ADR-025](ADR-025-addresses-become-what-they-mean.md), `GenerateReference.py` is deleted and nothing in the tree reads the file.

## Context

**What D3 said.** "The reference binary is committed so CI can run the oracle until Phase 4 ends." Phase 4 has ended, and nothing reads the file at runtime: the hosts load the image generated from it (ADR-019).

**What still read it:**
- `Tools/GenerateReference.py --check`, which CI ran;
- `ReferenceImageTests`, which loaded the file and the tables side by side;
- four `ExeLoaderTests`, which loaded the reference;
- `Tools/MapReference.py`, `ReferenceScreens.py` and `ScanReference.py`, by hand.

**What removing it does not do.** Removing the file does not stop the repository holding the original's bytes:
- the generated `ReferenceImage.cpp` holds all 98,080 bytes of its load image;
- git history keeps the file, and ADR-002 item 4 rules out rewriting history.

The owner was told this and ruled to remove it anyway.

## Decision

**1. `ELITES.EXE` is no longer tracked.** `.gitignore` lists `/ELITES.EXE`, so a local copy at the root, which the tools read, is never committed. The repository stays private (D2).

**2. The generated image keeps a guard without the file.**
- **`ReferenceImageTests.TheGeneratedImageIsTheReferences`** holds `REFERENCE_IMAGE` to `248c90724ebf8c4b94c85421638c337f928ffb2ac104001488a5c39381f9d35f`. That is the SHA-256 of the 98,080 bytes after the 64-byte MZ header, measured from the file whose own SHA-256 is ADR-007's, on 2026-10-10, before it left.
- **It also checks the header's facts and the seven relocations** against the file's values: entry 0000:0000, stack 13CA:03F8, allocation 001Ch to FFFFh.
- **It bites.** With one generated byte changed (CS:0007, F4h to F5h), it fails and prints both hashes.

**3. The loader keeps its tests on synthetic files.**
- The four `ExeLoaderTests` that loaded the reference now load MZ files built in the test. `MakeExecutable` takes several relocations and an entry point and stack.
- **What they cover:** relocation in any segment, MS-DOS's entry registers and RETF frame, the PSP and the environment, and `PatchByte` writing only over the byte it expects. They test the loader, not the game.
- **What covers the reference's own load:** the corpus, through `ReferenceExecutable()`.

**4. CI's `GenerateReference --check` step goes,** because its input is gone for good (AGENTS.md §6). The generator still runs against a local copy. Without one, it stops and says where the copy belongs.

**5. What is lost.**
- **Regenerating or re-verifying the tables in CI.** The image's guard is now the recorded hash, not the file.
- **Fresh annotations.** `ReferenceImage.cpp`'s comments name `Symbols.tsv` rows, and no CI step regenerates them any more. A renamed or moved symbol leaves them stale until someone runs the generator with a local copy. `GameData.h` and `DataOverlay.h` are still checked in CI (`GenerateOverlay --check`), because they need only the symbol table.
- **Tools without a local copy.** The mapping and screen tools work only where someone keeps the file at the root.

**6. Measured 2026-10-10, with the file absent:**

| Check | Result |
|---|---|
| `GameLogicTests` | 49 of 49 pass under g++ and clang++ |
| `MachineTests` | 133 of 133 pass under g++ and clang++ |
| The corpus | all 26 replays meet all 134 digests under `ReferenceRunner`, built with each compiler |
| clang++ warnings | none |
| The checkers | CheckFormat, CheckProjectFiles and `GenerateOverlay --check` are clean |

## What this forecloses

- **Committing `ELITES.EXE` again** without a new ruling.
- **A CI step or test that needs the file.**
- **Changing the generated image without a local copy of the file** and a new recorded hash.
