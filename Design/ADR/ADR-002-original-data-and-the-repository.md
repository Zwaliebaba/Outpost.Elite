# ADR-002 — Original data and the repository

**Status:** accepted 2026-10-09, from the owner's rulings D2 and D3 in [Reverse-Engineering-Plan.md §8](../Reverse-Engineering-Plan.md#8-decisions-for-the-owner). **Carried out 2026-10-09:** the owner made `Zwaliebaba/Outpost.Elite` private the same day.

## Context

`ELITEL.EXE` is a commercial copyright work. Its credits give the game to Bell & Braben and the code to Realtime Games Software Ltd, and Firebird published it. It is also a cracked copy (ADR-001). It has been on the public `main` since `4cfcee3`, so the original program, crack included, is being distributed from this repository.

A faithful port carries the original's bytes a second time, and that cannot be engineered away. The ship models, font, text, tables and the commander template are the game, and Phase 4 turns them into C++ tables. The C64 attempt in this repository's history had the same exposure as its risk R1 and, at its last revision, was still waiting on an answer from the rights holders.

AGENTS.md R14 puts third-party content under the owner's approval and asks for its licence text to travel with the bytes. The original comes with no licence, so this ADR is that approval, and there is no licence text to carry.

## Decision

1. **The repository becomes private (D2).** That stops further distribution of the binary and of anything derived from it. The owner made the change on 2026-10-09; before then the binary had been public on `main` since `4cfcee3`, together with the plan, ADRs and symbol table merged in PR #28.

2. **The reference binary stays in the tree** at the root, as `ELITEL.EXE`, byte-identical to the hash in ADR-001. Tooling (`Tools/ScanReference.py`), the Phase 2 host and the test suites read it from there. CI can therefore run every test that needs the original, with no secret and no private download.

3. **Original data is generated and checked in (D3).** In Phase 4 a script under `Tools/` extracts the ship models, font, text and tables from the reference into C++ source. The generated files are committed and reviewed like any other source, and the script stays so that the extraction can be repeated and checked. The shipping executable embeds them and does not need `ELITEL.EXE` at run time. Until Phase 4 the host reads the reference at start-up instead (ADR-001).

4. **History is not rewritten.** What the public period exposed stays in forks and caches whatever happens to this repository's history. A rewrite would cost every clone and buy little, and nobody has asked for one.

## What this forecloses

- **Publishing the repository as it stands.** Making it public again, or publishing a build, needs a new ADR first. That ADR would have to remove the binary and the generated tables from the tree and the history and read the data from the user's own copy at run time (the OpenRCT2 model), or else carry a written permission from the rights holders.
- A runtime dependency on the user's copy of the original in the shipping executable. The tables are compiled in.
- Treating the generated tables as hand-written source. They are regenerated by their script, never edited by hand.
