# Risk Register

**Status:** opened 2026-09-02 with the plan; **R2 closed and R1, R4, R8, R9 annotated the same
day** by the owner rulings and by slices 0a and 0c landing. Review at the end of each phase. A
risk that fires is marked **🔥 realised** with what happened — the useful part of a register is
the record of which guesses were right.

| # | Risk | Impact | Likelihood | Mitigation (designed in) | Early validation |
|---|---|---|---|---|---|
| R1 | **No licence upstream, and the intent is to publish.** The annotated source is copyright Braben & Bell (code) and Moxon (commentary), published on an educational, non-profit basis with an explicit *no licence, read and fork only*. A port is a derivative work — and as of the 2026-09-02 rulings the tree both **vendors ~3,000 unlicensed files** and is **intended for eventual publication**. Those two answers pull against each other, and together they are the largest exposure in the project. | **High** | Certain (it is the situation) | Structural, so the decision stays reversible in one command: everything not ours lives under `Upstream/` and **nowhere else** — no original assembler is copied into `GameLogic/`, `Tests/` or `Design/`; the assembled reference binaries are **never committed**; generated data tables are checked in and are explicitly in scope for the permission request. Nothing is pushed to a public remote until 0e closes. Fallback if permission is refused: the private posture, with `Upstream/` excised from the published history rather than deleted at the tip. | **Slice 0e** — approach the rights holders. Until it closes this row is open by definition, and it is the one risk that no amount of engineering retires. |
| R2 | ✅ **closed 2026-09-02** — **The include tree is not here.** The 13 masters referenced 710 library files and a font binary that were absent; without them nothing could be ported. | High | Was certain | Slice 0a obtained the tree and pinned it at `aa3f7ee` so the masters and the library cannot drift apart. | **Met and standing.** 712/712 include paths resolve, the font resolves, and all 13 masters are byte-for-byte identical to their upstream copies. `tools/inventory.py --check-includes` re-proves it in a second, so drift is caught rather than assumed away. |
| R3 | ⚠️ **Mitigation withdrawn 2026-09-03.** **Cadence has no oracle.** The original's main loop ran as fast as the machine allowed; the feel of flight (speed, roll and pitch rates, how fast enemies close) follows from that rate, and no routine-level test captures it. | Med | **High** | ~~Measure iterations per second in VICE in three scenes and derive the fixed rate from it.~~ **The owner has ruled out the emulator entirely, so this row no longer has a mitigation.** Two candidates, neither chosen: give the interpreter a cycle count and measure a main-loop iteration against the processor clock, which actually measures something; or pick a default near 10 to 20 steps per second, expose it in configuration and tune by feel. The rate stays a config value either way. | **Nothing validates this before slice 2e**, which is the first build a person can fly. Whoever takes 2e must pick one of the two options above and say which, because "it felt about right" and "we measured it" are different claims and only one of them survives being asked about later. |
| R4 | **6502 semantics leak.** Carry/overflow reuse, sign-magnitude coordinates, self-modifying operands, stack-popping returns, BCD, and routines that fall through into the next one: any of these can be mistranslated and still *look* right. | High | High | Bit-exact integer model (ADR-002); the oracle tests every pure routine on exhaustive 8-bit inputs (ADR-003 §1); porting principles §4.4 (document each trick at the call site). | 🔥 **Realised once, 2026-09-03 (slice 1b-b), and caught in a minute.** The port of the sixteen-step long division restarted the carry flag on every loop step; the original threads it through, so that what falls out of the top of the quotient is shifted into the remainder on the next step. Both versions read as a rotate, a compare, a conditional subtract and two rotates, and **nothing about the wrong one looks wrong**. It failed on the first case swept, naming the routine, the iteration and both numbers. This is the exact defect class the row predicted, the mitigation caught it at the cost of one rebuild, and the fix carries a comment so it does not get simplified back. **Substantially de-risked 2026-09-03 (slice 1b-a).** Nine routines built on exactly the hazards this row names — carry chained between shifts and additions, sign-magnitude operands, a deliberate off-by-one that cancels against a set carry flag, a subtract-and-negate branch — matched the shipped code over **all 65,536 input pairs each**, with the addition swept over 200,000 cases and its edges pinned by hand. The approach works, and the cost per routine is now known: read it, port it, write one exhaustive comparison. What is *not* yet evidence is the harder material — self-modifying operands, routines that discard their return address, and the drawing code's fall-through chains are all still ahead. **First evidence, 2026-09-02 (slice 0c).** The generator is exactly this risk in miniature — a carry chained from a rotate into one addition and on into a second, with each half storing a byte its partner just read — and the ported version agreed with the interpreter on the returned byte, the previous byte, C, V and all four state bytes over 60,000 iterations and 8,192 first calls. One routine is not a trend, but the *harness* is now proven, which is what phase 1 was going to spend its first sitting establishing. The interpreter's own suite also handles the stack-popping-return case: a run that unwinds past its entry point is reported as completed rather than spinning to the budget. |
| R5 | **Hardware effects reproduced wrongly.** Sprites (scanner blips, crosshairs, Trumbles), the raster interrupt that recolours the dashboard mid-frame, multicolour cell constraints, and erase-by-EOR all produce pixels by mechanisms the port does not have. | Med | Med | Emulate by effect (§4.5): the canvas draws the same pixels. **Revised 2026-09-03**: with the emulator gone, the check is no longer a screenshot comparison but the oracle itself — the game's drawing routines write a bitmap into the 64 KB image, so a test decodes those bytes and compares pixel for pixel. Exact rather than eyeballed, and it reaches further than a screenshot did. | 1d: the first drawing routine compared against the bitmap the shipped code produces. What the oracle still cannot judge is anything the VIC-II did *outside* the bitmap — sprite overlay and the mid-frame palette split — and those stay a matter of reading the hardware's behaviour carefully and saying so in the code. |
| R6 | **SID fidelity.** A hand-written three-voice synthesiser will not sound like a 6581/8580 (filter, combined waveforms, ADSR bugs). | Low | High | Register-write logs are oracle-tested (the *player* is exact even if the *synth* is approximate); the synth is in the executable, swappable; fallback is recorded samples (plan §5.2). | 5a: audible comparison with VICE for the laser, explosion and hyperspace sounds. |
| R7 | **Modernising before the port is faithful.** Higher resolution, smooth motion, gamepad, "just fix that bug" — each is reasonable and each breaks the oracle's meaning if done early. | Med | High | ADR-001 §4: phase 6 is gated on every fidelity suite green with options off; known bugs are ported and listed, not fixed (§4.7). | Every slice's accept is a fidelity check; there is no slice before phase 6 whose accept is "nicer". |
| R8 | **The shell template.** `Outpost.vcxproj` is a WinUI 3 / MSIX single-project template pulling WebView2, AI/ML, Widgets and Search packages; building and debugging a pixel-blit game through it is friction with no return. | Med | Med | **Settled 2026-09-02**: MSIX packaging stays, WinUI 3 and the unused packages go (ADR-005 §5). The residual risk moved rather than vanished — it is now the packaged-launch debug loop, which is slower than launching a bare exe, so 0d must keep **both** launch paths working. | 0d: a window that opens, resizes and closes cleanly **packaged and unpackaged**, and a `packages.config` listing only what is used. |
| R9 | **The oracle is silently absent.** The label map and binaries are not committed; a machine without them skips every oracle test and the suite looks green. | Med | Med | **Built 2026-09-03.** Oracle tests log the missing file *and the command that produces it*, then pass; one dedicated test, `OracleIsPresent`, fails instead. The config file the ADR originally specified was dropped — `OracleImage` finds the repository root from its own module path, so there is nothing to misconfigure and nothing to keep in step per machine (ADR-003 §1, amended). | ✅ **Exercised 2026-09-03.** `Labels.txt` was renamed away and the suite re-run: 20 passed, **exactly one failed** (`OracleIsPresent`), the four oracle tests logged `SKIPPED -- oracle absent` naming the missing file, and both the log line and the assertion carried the command that fixes it. The mechanism is tested rather than merely written, which is the distinction this row exists to enforce. |
| R10 | **Golden images are brittle.** A one-pixel change in a shared primitive invalidates dozens of goldens and tempts a blanket re-record. | Low | Med | Goldens are few and named for what they prove; a re-record needs a visual diff (`tools/golden_diff.py`) attached to the change; the oracle, not the golden, is the authority for anything it can reach. | 1d: the harness lands with diff output from the first golden. |
| R11 | **Inventory drift.** 710 files and ~45 C++ homes: a routine gets ported into a different file than the ledger says, or forgotten, and the ledger stops being true. | Low | High | `tools/inventory.py` cross-checks `Source-Inventory.md` against the include list and against `// 6502:` comments in `GameLogic/` (slice 0c); CI fails on an unaccounted label. | 0c: the check runs with everything *Pending*. |
